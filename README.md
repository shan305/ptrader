# PTrader

A self-contained demo trading backend: demo accounts, FX and metals symbols,
bid/ask quotes, market orders with simulated fills, positions, floating and
realized P&L, and trade history, exposed through FastAPI and persisted with
SQLAlchemy (SQLite by default). No external broker is needed.

## Quick start

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn ptrader.main:app --reload
```

Open http://127.0.0.1:8000/docs for the interactive API. On startup the
database schema is migrated to the latest revision and any missing default
symbols are seeded with an opening quote. `GET /health` reports readiness and
background worker status.

Run the tests:

```bash
pytest -q
```

## Configuration

Environment variables (or a `.env` file, see `.env.example`):

| Variable | Default | Purpose |
|---|---|---|
| `PTRADER_DATABASE_URL` | `sqlite:///./ptrader.db` | Any SQLAlchemy URL |
| `PTRADER_AUTO_MIGRATE` | `true` | Apply pending migrations on startup; when `false`, startup fails unless the schema is current |
| `PTRADER_SEED_ON_STARTUP` | `true` | Insert missing default symbols and quotes |
| `PTRADER_QUOTE_RETENTION_PER_SYMBOL` | `10000` | Quotes kept per symbol (oldest are deleted on ingestion); `0` keeps all |
| `PTRADER_SIMULATOR_ENABLED` | `false` | Generate random-walk ticks in the background |
| `PTRADER_SIMULATOR_INTERVAL_SECONDS` | `1.0` | Tick interval for the background simulator |
| `PTRADER_SIMULATOR_SEED` | none | Seed for reproducible simulated prices |
| `PTRADER_WORKER_STOP_TIMEOUT_SECONDS` | `5.0` | How long shutdown waits for a worker's current run before cancelling it |

## Architecture

```
api/            HTTP layer: parses requests, opens a UnitOfWork, formats responses
services/
  orders.py     order lifecycle: pre-trade checks -> execution -> risk -> accounting, or rejection
  execution.py  MarketExecution: fill price from the latest quote (buys at ask, sells at bid)
  positions.py  position accounting: open, reduce/close, margin release, valuation
  ledger.py     the only code that changes a balance; one ledger entry per money-moving deal
  accounts.py   accounts, deposits/withdrawals, equity/margin metrics
  market_data.py QuotePipeline (ingestion) and quote history queries
  simulator.py  random-walk quote source, fed through the pipeline
  pricing.py    pure calculations: conversion rates, margin, profit
  symbols.py, seed.py
uow.py          UnitOfWork: transaction boundary + after-commit event dispatch
events.py       EventBus and domain events
workers.py      BackgroundWorker / WorkerManager
migrate.py, migrations/   Alembic migrations
```

**Transaction boundaries.** Each command function in `services` (create
account, deposit, place order, ingest quotes, ...) opens exactly one
`with uow.transaction():`. The components it calls only add and flush. A
command either commits completely or rolls back completely. An order rejected by a
business rule is the one two-step case: the execution transaction is rolled
back, then the rejected order is stored in its own transaction.

**Ledger.** `Account.balance` is a cached running total of `ledger_entries`.
Every entry references the deal that caused it (a balance deal for deposits
and withdrawals, an exit deal for realized profit), and stores
`balance_after`. `GET /accounts/{id}/ledger` lists it.

**Market data.** Every quote, whether pushed through the API, generated by the
simulator or seeded, goes through `QuotePipeline`: it resolves the symbol,
rounds to the symbol's digits, checks bid/ask, rejects quotes timestamped in
the future or older than the symbol's latest quote, stores the quote with its
`source`, publishes `QuoteReceived`, and trims history to the retention limit.

**Events.** Commands emit domain events (`QuoteReceived`, `OrderFilled`,
`OrderRejected`, `PositionOpened`, `PositionReduced`, `BalanceChanged`). They
are dispatched synchronously after commit and discarded on rollback. A failing
handler is logged and never affects the command. Subscribe with
`app.state.events.subscribe(EventType, handler)`.

**Lifecycle.** Startup migrates, seeds, then starts workers. Shutdown stops
workers first and waits for any run in progress, then disposes the engine.
Shutdown also runs if startup fails part-way. Failing worker runs are retried
with exponential backoff and reported in `/health`.

## Database and migrations

The schema is managed by Alembic (`ptrader/migrations`). The app upgrades
automatically on startup. A database created by PTrader 0.1 (before
migrations) is detected, stamped as revision `0001` and upgraded; its ledger is
rebuilt from its existing deals. On SQLite the whole migration runs in one
transaction, so a failed upgrade leaves the database unchanged.

```bash
alembic current            # uses PTRADER_DATABASE_URL
alembic upgrade head
alembic downgrade 0001
```

Integrity rules are enforced by the database, not only by the code: foreign
keys (enabled on SQLite), CHECK constraints on value ranges and enum values,
consistency of record states (for example, a closed position has zero volume
and margin, a filled order has a price and position, a balance deal never
refers to an order), at most one deal per order and one ledger entry per deal.
Decimal columns are stored as text for exactness; constraints compare them
with `CAST(... AS NUMERIC)`.

## Trading rules

- **Fills**: buys fill at the ask, sells at the bid. A buy position is closed
  at the bid, a sell position at the ask.
- **Hedging**: each order without `position_id` opens a new position. An
  order with `position_id` (opposite side) closes all or part of it;
  `POST /positions/{id}/close` does the same.
- **Volume**: must be within the symbol's min/max and a multiple of its step.
  A partial close may not leave less than the minimum volume.
- **Margin**: `volume × contract size × price ÷ leverage`, converted to the
  account currency. An order is rejected if it needs more than free margin.
- **P&L**: `(close − open) × volume × contract size`, sign-flipped for sells,
  converted from the symbol's profit currency into the account currency
  through the latest mid price of a direct or inverse pair (e.g. JPY → USD
  via USDJPY).
- **Account metrics**: equity = balance + floating P&L; free margin = equity −
  margin; margin level = equity ÷ margin × 100.
- Prices are rounded to the symbol's digits, money to cents. All arithmetic
  uses `Decimal`, stored as text so it stays exact in any database.

### Rejections

Unknown accounts, symbols or positions return `404`; malformed requests return
`422`. Once the account and symbol are known, any other failure (volume rules,
disabled account or symbol, insufficient margin, missing quote or conversion
rate, invalid close) is **stored as an order with status `rejected`** and
returns `422` with `{"detail": "...", "order_id": n}`.

## API overview

All routes are under `/api/v1`.

| Method & path | Purpose |
|---|---|
| `POST /accounts` | Create a demo account (`name`, `currency`, `leverage`, `initial_deposit`) |
| `GET /accounts`, `GET /accounts/{id}` | List accounts / account with equity, margin, free margin |
| `PATCH /accounts/{id}` | Change `name`, `leverage` (not with open positions), `is_active` |
| `POST /accounts/{id}/deposit`, `/withdraw` | Balance operations |
| `GET /accounts/{id}/positions?status=open\|closed\|all` | Positions with live price and floating P&L |
| `GET /accounts/{id}/orders?status=filled\|rejected` | Order history |
| `GET /accounts/{id}/deals` | Deal history (balance operations, entries and exits) |
| `GET /accounts/{id}/ledger` | Balance changes with running balance |
| `GET /symbols`, `POST /symbols`, `GET/PATCH /symbols/{name}` | Symbol catalogue |
| `GET /quotes`, `GET /quotes/{symbol}` | Latest quotes |
| `GET /quotes/{symbol}/history?limit=&since=&until=` | Recent quotes, newest first |
| `POST /quotes` | Push an external quote (`symbol`, `bid`, `ask`, optional `time`, `source`) |
| `POST /quotes/simulate` | Generate `steps` random ticks for all or listed symbols |
| `POST /orders` | Place a market order |
| `GET /orders/{id}` | Order details |
| `GET /positions/{id}`, `POST /positions/{id}/close` | Inspect or (partially) close a position |

### Example

```bash
curl -X POST localhost:8000/api/v1/accounts -H 'content-type: application/json' \
  -d '{"name": "Demo", "initial_deposit": 10000, "leverage": 100}'

curl -X POST localhost:8000/api/v1/orders -H 'content-type: application/json' \
  -d '{"account_id": 1, "symbol": "EURUSD", "side": "buy", "volume": 0.1}'

curl -X POST localhost:8000/api/v1/quotes/simulate -H 'content-type: application/json' -d '{"steps": 10}'

curl localhost:8000/api/v1/accounts/1/positions

curl -X POST localhost:8000/api/v1/positions/1/close
```

## Limitations

- Market orders only; no pending orders, stop loss / take profit, swaps,
  commissions or stop-out.
- Executions are serialised with an in-process lock, so run a single server
  process; there is no cross-process execution safety yet.
- No authentication.
- Events are in-process and not persisted; a subscriber that is down misses them.
